# Code Coverage Strategy

## Tool: cargo-tarpaulin

We use cargo-tarpaulin with LLVM engine for code coverage analysis.

## Philosophy

- Coverage is a **diagnostic tool** to find untested code, not a metric to chase
- No coverage thresholds or gates - it should not block development
- Focus on testing business logic, not boilerplate

## What We Exclude

### Entire Files (via tarpaulin.toml)
- `crates/recon_derive/src/*` - Procedural macro crate
- `crates/diesel_models/src/schema.rs` - Auto-generated by Diesel
- `crates/recon/src/bin/recon.rs` - Binary entry point
- `crates/common_utils/src/logging.rs` - Logging infrastructure setup

### Specific Functions (using attributes)
- Simple Debug/Display trait implementations
- Boilerplate From/Into conversions

## How to Exclude Code

1. **For entire files** - Add to `exclude-files` in `tarpaulin.toml`:
   ```toml
   exclude-files = [
       "crates/path/to/file.rs",  # Reason for exclusion
   ]
   ```

2. **For specific functions** - Use conditional compilation:
   ```rust
   #[cfg(not(tarpaulin_include))]
   impl Display for MyType {
       // This won't be included in coverage
   }
   ```

Note: The `#[cfg_attr(tarpaulin, ignore)]` attribute is for ignoring tests, not files.
The `#[cfg_attr(tarpaulin, skip)]` attribute only works on nightly Rust.

## Commands

```bash
# Generate HTML coverage report
just coverage

# Quick summary in terminal
just coverage-summary

# Generate and open report
just coverage-open
```

## Why This Approach?

1. **Explicit exclusions** - You see in code reviews when coverage is skipped
2. **Granular control** - Skip specific functions, not entire modules
3. **Self-documenting** - The code shows what's excluded and why
4. **No hidden configuration** - Everything is visible in the codebase
